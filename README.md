# Dataset Generator — датасеты по криминалистике

Программа превращает документы по криминалистике в обучающие датасеты для ИИ-ассистента
по криминалистике и судебной экспертизе. Источником может быть что угодно: научные статьи,
исследования, диссертации и авторефераты, отчёты, экспертные заключения, обзоры практики,
методички, учебники, книги — в форматах PDF, DOCX, EPUB, FB2, DjVu, TXT, HTML и др. Текст
обрабатывает локальная модель **Qwen3 8B через Ollama** — ничего не уходит в интернет.

Возможности:

- терминальный интерфейс (TUI), в котором в реальном времени видно, как модель «думает»;
- несколько типов датасетов на выбор — или модель подбирает тип сама;
- отдельный тип датасета для разбора научных исследований;
- язык датасета определяется по языку источника;
- списки литературы и колонтитулы (название журнала, DOI, номера страниц) вырезаются
  автоматически — модель не тратит на них время;
- оценка времени обработки по замеру скорости модели на вашем ПК;
- возобновление с места остановки, защита от дубликатов;
- форматы записей `chatml`, `alpaca`, `sharegpt` в JSON Lines.

## Установка

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и [Ollama](https://ollama.com).

```bash
sudo systemctl enable --now ollama   # или просто: ollama serve
ollama pull qwen3:8b                 # ~5 ГБ
uv sync                              # зависимости проекта
```

Для DjVu дополнительно нужен `djvulibre` (`sudo dnf install djvulibre`).

## Быстрый старт

1. Положите документы в папку `input/`.
2. Запустите `uv run dataset-generator`.
3. Введите имя файла (или путь к файлу/папке) и нажмите Enter.
4. Выберите тип датасета в появившемся окне и нажмите «Начать».
5. Готовые датасеты появятся в папке `datasets/`.

## Интерфейс

```
┌ поле ввода: имя файла или путь ──────────────────────────────────────────┐
├ Настройки ─────────┬ 🧠 Размышления модели (поток в реальном времени) ───┤
├ Очередь ───────────┤                                                     │
├ прогресс ──────────┼ 📝 Ответ модели (JSON) ─────────────────────────────┤
├ Статистика и время ┤                                                     │
├ ПК и скорость ─────┼ 📚 Датасет и журнал: готовые примеры, события ──────┤
└────────────────────┴─────────────────────────────────────────────────────┘
```

| Клавиша | Действие |
|---|---|
| Enter | добавить файл или папку в очередь (пустой Enter — перезапустить очередь) |
| → | принять автодополнение пути |
| ↑ ↓ / Tab / Enter / Esc | выбор типа и формата в окне выбора |
| F2 | включить/выключить мышление модели (со следующего фрагмента) |
| F3 | остановить обработку (прогресс сохраняется) |
| F4 | очистить панели |
| Ctrl+Q | выход |

Файлы можно добавлять прямо во время работы — они встают в очередь, у каждого свой тип.

## Типы датасетов

В окне выбора справа показан пример для каждого типа и то, как выглядит строка датасета.

| Тип | Ключ | Что получится | Лучше всего для |
|---|---|---|---|
| 🔀 **Авто — по фрагментам** (рекомендуется) | `mixed` | модель для каждого фрагмента сама выбирает 1–2 подходящих типа; примеры раскладываются по отдельным файлам — по одному на тип | любых документов, особенно разнородных |
| 🔎 Авто — по документу | `auto` | модель читает начало, середину и конец документа (у короткой статьи — весь текст), определяет жанр и выбирает один тип на весь документ | однородных документов |
| ❓ Вопрос — ответ | `qa` | определения, объяснения, классификации, процедуры, правовые вопросы | учебники, лекции, справочники, обзорные статьи |
| 🔬 Разбор исследований | `research` | цель, методы и выборка, результаты, ограничения и практическое значение исследования | научные статьи, диссертации, отчёты об экспериментах |
| 🧩 Ситуационные задачи | `cases` | фабула происшествия → разбор действий следователя и эксперта | методики расследования, практика |
| 📋 Инструкции и задания | `instructions` | «Составь план…», «Перечисли признаки…» → образцовое выполнение | методички, наставления, руководства |
| 🧠 С рассуждением | `reasoning` | вопрос → пошаговое рассуждение в `<think>…</think>` → вывод | монографии, экспертные заключения, аналитические статьи |
| 💬 Диалоги | `dialogue` | беседа из 2–4 реплик с уточняющими вопросами | обзорные тексты, учебные пособия |

Выбор режима «по документу» запоминается: при повторном запуске документ не анализируется
заново.

**Язык.** Промпты для модели написаны на английском: большинство источников англоязычные,
и Qwen3 точнее следует английским инструкциям. Язык самих примеров определяется
автоматически по тексту источника: английская статья даёт английский датасет, русская —
русский. System-промпт в примерах тоже на языке источника. Задать язык вручную:
`--language en`.

**Научные материалы.** Результаты конкретного исследования попадают в датасет как результаты
исследования — с объектом, выборкой и методом, а не как общепризнанный факт. Авторская позиция
подаётся как одна из точек зрения, ссылки вида `[12]` в примеры не переносятся. Аннотации,
ключевые слова, сведения об авторах и благодарности модель пропускает.

## Оценка времени

Модель не знает, насколько быстро она работает на конкретном ПК, поэтому время не
«спрашивается» у неё, а **измеряется**:

1. Перед первым фрагментом программа отправляет настоящий запрос с ограничением в несколько
   токенов и замеряет скорость чтения и генерации — с учётом длины промпта и JSON-схемы.
   Замер делается один раз за сеанс и почти ничего не стоит: прочитанный промпт Ollama
   кеширует для реального запроса.
2. По скорости, размеру фрагментов и типу датасета считается прогноз с диапазоном
   («≈ 3 ч 10 мин, от 1 ч 55 мин до 5 ч 20 мин»).
3. После каждого фрагмента оставшееся время уточняется по фактической длительности.

В панели «ПК и скорость модели» видно процессор, потоки, ОЗУ, где работает модель
(CPU или GPU) и измеренные скорости. Если замер не удался, оценка строится грубо — по размеру
модели и типу устройства.

## Результат

Все файлы пишутся в `datasets/` в формате JSON Lines (одна строка — один пример):

| Режим | Файлы |
|---|---|
| конкретный тип или «по документу» | `<файл>.<тип>.jsonl`, например `article.pdf.research.jsonl` |
| «по фрагментам» | `<файл>.mixed.<тип>.jsonl` — по файлу на каждый выбранный моделью тип |

Рядом лежит `*.state.json` — служебный файл для возобновления.

Формат записи выбирается в окне выбора или флагом `--format`. Пример `chatml`
(по умолчанию):

```json
{"messages": [
  {"role": "system", "content": "Ты — ИИ-ассистент по криминалистике…"},
  {"role": "user", "content": "Как фиксируют объёмные следы обуви на снегу?"},
  {"role": "assistant", "content": "1. След фотографируют по правилам масштабной съёмки…"}
 ],
 "metadata": {"source": "trasology.pdf", "chunk": 3, "kind": "qa", "category": "трасология",
              "type": "procedure", "language": "ru", "model": "qwen3:8b"}}
```

- `alpaca` — `instruction`, `input`, `output`, `system`, а у диалогов ещё `history`;
- `sharegpt` — `conversations` из реплик `system` / `human` / `gpt`.

Такие файлы понимают Hugging Face `datasets`, TRL, Unsloth, Axolotl, LLaMA-Factory:

```bash
cat datasets/*.jsonl > forensics.jsonl          # всё вместе
cat datasets/*.qa.jsonl > forensics-qa.jsonl    # только «вопрос — ответ» из всех файлов
```

```python
from datasets import load_dataset

ds = load_dataset("json", data_files="forensics.jsonl", split="train")
```

**Возобновление.** Если работа прервалась (F3, Ctrl+Q, Ctrl+C, выключение ПК), добавьте тот же
файл с тем же типом снова — обработка продолжится с места остановки. Если изменился сам
файл или настройки нарезки, формата или языка, старый датасет не удаляется, а переименовывается
в `*.jsonl.bak-<дата>`.

## Командная строка

```
uv run dataset-generator [ФАЙЛЫ ...] [ОПЦИИ]
```

`ФАЙЛЫ` — имена файлов (ищутся в текущей папке, затем в `input/`) или папки (берутся все
поддерживаемые файлы внутри). Без файлов открывается пустой TUI, где файл вводится вручную.
Без `-k` тип датасета спрашивается: в TUI — окном выбора, в режиме `--no-tui` — меню в
терминале (если ввода нет, например в скрипте, берётся `mixed`).

Примеры:

```bash
uv run dataset-generator                                # TUI, всё вручную
uv run dataset-generator article.pdf                    # TUI, спросит тип датасета
uv run dataset-generator -k mixed input/                # вся папка, модель выбирает типы сама
uv run dataset-generator -k research input/articles/    # разбор исследований из статей
uv run dataset-generator -k qa -f alpaca book.fb2.zip   # конкретный тип и формат
uv run dataset-generator --no-tui -k mixed input/       # без TUI: вывод потоком в терминал
uv run dataset-generator --no-think -k cases book.pdf   # без мышления — в разы быстрее
uv run dataset-generator --help                         # справка по всем опциям
```

| Опция | По умолчанию | Назначение |
|---|---|---|
| `-k, --kind` | спросить | `mixed`, `auto`, `qa`, `research`, `cases`, `instructions`, `reasoning`, `dialogue` |
| `-f, --format` | `chatml` | формат записей: `chatml`, `alpaca`, `sharegpt` |
| `--language` | `auto` | язык датасета: `auto` — как у источника, или код (`ru`, `en`, `uk`…) |
| `--no-system` | — | не добавлять system-промпт в примеры |
| `-m, --model` | `qwen3:8b` | модель Ollama |
| `--host` | `OLLAMA_HOST` или `localhost:11434` | адрес Ollama |
| `-i, --input-dir` | `input` | где искать файлы по имени |
| `-o, --output-dir` | `datasets` | куда писать датасеты |
| `--chunk-size` | `3000` | размер фрагмента текста, символов |
| `--overlap` | `300` | перекрытие соседних фрагментов, символов |
| `-n, --max-items` | зависит от типа | максимум примеров на фрагмент (qa и mixed — 5, research и instructions — 4, cases и reasoning — 3, dialogue — 2) |
| `--num-ctx` | `16384` | контекстное окно модели, токенов |
| `--num-predict` | `8192` | лимит генерации на фрагмент, включая размышления |
| `--retries` | `2` | повторы при ошибке (последняя попытка — без мышления) |
| `--no-think` | — | выключить режим мышления Qwen3 |
| `--no-tui` | — | простой потоковый вывод вместо TUI (удобно для фоновых запусков) |

## Поддерживаемые файлы

PDF, EPUB, MOBI, FB2 (в том числе `.fb2.zip`), DjVu, DOCX, TXT/MD (кодировка определяется
автоматически, включая cp1251), HTML (например, сохранённые веб-страницы статей), XPS, CBZ.
Сканы без текстового слоя нужно сначала распознать, например `ocrmypdf scan.pdf out.pdf`.

При извлечении текста убираются номера страниц, переносы слов, повторяющиеся колонтитулы
PDF и списки литературы (в журнале TUI пишется, сколько записей вырезано).

## Советы по скорости

Без поддерживаемой видеокарты Ollama работает на CPU: статья на 10–15 страниц занимает
примерно от получаса до пары часов, книга на 300 страниц — много часов. Точную цифру для
вашего ПК покажет оценка времени. Ускоряют работу:

- `--no-think` или F2 — без размышлений модель отвечает примерно вдвое быстрее;
- `--chunk-size 5000` — меньше запросов;
- конкретный тип вместо `mixed` — промпт короче;
- `--no-tui` — запуск в фоне, например в `tmux`.

## Устройство проекта

```
src/dataset_generator/
├── cli.py          аргументы командной строки
├── tui.py          интерфейс на Textual;  kind_picker.py — окно выбора типа
├── console.py      режим без TUI
├── pipeline.py     конвейер: файл → язык и тип → фрагменты → модель → датасет
├── kinds.py        типы датасетов: схемы ответа, задачи для промпта, примеры
├── prompts.py      промпты эксперта-криминалиста (на английском)
├── llm.py          запросы к Ollama, анализ источника
├── estimate.py     характеристики ПК, замер скорости, прогноз времени
├── extract.py      извлечение текста;  language.py — определение языка
├── chunking.py     нарезка на фрагменты, удаление списков литературы
└── dataset.py      форматы записей, запись JSONL, возобновление
```

Проверка кода: `uv run ruff check .` и `uv run ruff format .`
